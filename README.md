# Собеседник в аэропорту (passenger-chat)

Мобильное одностраничное приложение: пассажиры оставляют имя, телефон и темы
для общения, видят список желающих поговорить и находят контакт для связи в
мессенджере. Записи хранятся до 00:00 по московскому времени (TTL в Redis).

Стек: Next.js 14 (App Router) + Tailwind + Upstash Redis (бесплатный тариф,
подключается через Vercel Marketplace).

## Структура

- `app/page.js` — оркестрация трёх экранов (форма / список / модалка), состояние в localStorage.
- `components/RegisterForm.jsx` — экран 1: форма.
- `components/PeopleList.jsx` — экран 2: список + табы по темам + кнопки внизу.
- `components/ContactModal.jsx` — экран 3: модалка с номером и инструкцией.
- `components/EditTopicsModal.jsx` — модалка смены тем.
- `app/api/*` — серверные роуты (register/list/reveal/update-topics/leave/me).
- `lib/redis.js` — клиент Upstash Redis.
- `lib/time.js` — расчёт TTL до полуночи МСК.
- `lib/topics.js` — список тем (правь под себя).
- `app/privacy/page.js` — страница-заглушка политики ПДн (см. примечание ниже).

## Деплой на Vercel через свой GitHub

### 1. Публикуем код в свой репозиторий

```bash
cd passenger-chat
git init
git add .
git commit -m "init: passenger chat app"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/passenger-chat.git
git push -u origin main
```

### 2. Создаём проект в Vercel

1. Зайти на vercel.com → **Add New → Project**.
2. Импортировать репозиторий `passenger-chat` из GitHub (потребуется дать
   Vercel доступ к репозиторию/организации).
3. Framework Preset определится автоматически как **Next.js** — ничего менять
   не нужно, жмём **Deploy** (на этом этапе можно, сборка пройдёт, но без базы
   API-запросы будут падать — это нормально, база добавляется следующим шагом).

### 3. Подключаем бесплатную базу (Upstash Redis)

1. В проекте на Vercel: вкладка **Storage → Create Database → Upstash → Redis**
   (или **Marketplace Database Providers → Upstash**, в зависимости от текущего
   UI Vercel).
2. Выбираем бесплатный тариф (Free / Pay as you go с бесплатным лимитом).
3. После создания Vercel сам пропишет переменные окружения в проект —
   обычно `KV_REST_API_URL` / `KV_REST_API_TOKEN` либо
   `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`. Код в `lib/redis.js`
   поддерживает оба варианта названий — ничего дополнительно переименовывать
   не нужно.
4. Если переменные не подтянулись автоматически — Settings → Environment
   Variables → добавить руками значения из консоли Upstash (REST API URL и
   REST API Token), для окружений Production/Preview/Development.

### 4. Передеплой

После добавления базы: Deployments → на последнем деплое **... → Redeploy**
(чтобы подхватились новые переменные окружения).

### 5. Проверка

Открыть выданный Vercel URL с телефона (или DevTools в режиме мобильного
устройства) — должна открыться форма. Заполнить, нажать «Начать поиск» —
должен появиться экран списка (изначально пустой, пока нет других записей).

## Локальный запуск (опционально)

```bash
npm install
cp .env.example .env.local   # вписать KV_REST_API_URL / KV_REST_API_TOKEN
npm run dev
```

## Важно про 152-ФЗ и `/privacy`

Приложение собирает имя и телефон — это персональные данные. Страница
`/privacy` — это заглушка-шаблон, а не готовый юридический текст. Перед
реальным использованием (особенно в контексте вашей организации как субъекта
КИИ) текст политики и форма получения согласия должны быть согласованы с
ИБ/юристом.

## Известные ограничения текущей реализации

- Список обновляется поллингом раз в 5 секунд (без WebSocket/SSE) — этого
  достаточно для zала ожидания, но не realtime в строгом смысле.
- Модерации контента/имён нет.
- Списки очищаются лениво: запись реально удаляется из Redis по TTL, а из
  индекса (`active_users`) — при следующем обращении к `/api/list`
  (`ZREMRANGEBYSCORE`). Разово это не критично, но при нулевом трафике ночью
  индекс почистится только на первый запрос следующего дня.
